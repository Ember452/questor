## 1. 一句话结论

- **P0（接口骨架）：达成（GO）。** 冷导入、构造不变式、三道分层守卫 + 协议单一真源 self-test 全绿，均可复现（见 §8 实测）。
- **P1（最小可跑循环）：不可判完成（NO-GO 进 P2）。** 核心 happy-path / deny / 取消 **在真实代码路径上确实跑通**（fake provider，无 key），但存在 **6 个 Blocker/阻断级缺陷**，其中 2 个是我**当场复现出来的崩溃/数据污染**：
  1. **C2 假不可变**（frozen dataclass 的叶层 `dict` 可变，且经 COW 在 old/new 态间共享 → 一处改动污染"不可变"历史，已复现泄漏）；
  2. **Cancel 路径 seq 碰撞** → 落库直接 `IntegrityError`（已复现，取消带在途工具时会撕裂持久层，违 C7/ADR-0011/DoD②）；
  3. **checkpoint / 断点恢复根本未接线**（§2.5-5 与 DoD⑥ 未达成，无任何 rehydrate/resume API，loop 从不写/读 checkpoint）；
  4. **护栏与终止梯度全是死字段**（`repeat_tool_limit/max_tokens/deadline_seconds/max_consecutive_continuations` 定义但 loop 只读 `max_turns`，违反 plan T7 / 04 §3）；
  5. **沙箱 / capability-risk fail-closed deny 未接线**（`SandboxPort`/`NullSandbox`/`spec.capability`/`spec.risk` 均无消费者，plan §1.2 声称 P1 就做的 "none→deny" 未实现）；
  6. **入口与活文档腐化**：`python -m questor` 仍打印"P0 no runnable agent yet"（未接 CLI）；CHANGELOG `[Unreleased]` 完全没有 P0/P1 代码条目（违 AGENTS §5.5）。
- **是否可进 P2：NO-GO**，直到 Blocker #1/#2 与"阻断"项 #3/#5 修好并补上能证伪它们的测试。

## 4. 假完成与偷懒清单（A–G，含严重度）

**A. 假完成 / 声称做完其实没做（Blocker / 阻断）**

- **A2｜终止梯度 + 护栏**（**阻断**）：`loop.py:100-140` 只有 `max_turns`→failed + 顶部 `cancel_event` 探针。plan T7 明列 `[P1]` 的"拒绝过早 Finish/stall nudge/grace call/强制总结/重复检测/续跑上限/idle 看门狗"**全部无实现**；`Budget` 四个阈值字段**死字段**（§8 grep：loop 只读 `max_turns`）。

- **A4｜入口陈旧**（**应修**）：`__main__.py:11-13` 仍打印 "P0 interface skeleton — no runnable agent yet"，不接 `surfaces.cli`；无 `console_scripts`。§8-A 复现。

## 5. 扩展有害的结构（前瞻反噬）

1. **C2 假不可变 → 反噬 P3/P4**：`args/input/payload/data` 裸 dict 被 COW 跨态共享（§8-H 实证）。P3 事件溯源/回放、P4 记忆会**基于"状态不可变"假设**重建历史；一旦某策略/工具原地改叶 dict，**已持久化的 history 与新态同时被污染**，回放/分支当场作废——正是 HARD-CONSTRAINTS C2 说的"最难查的 bug"。越晚发现，越要把所有 frozen dataclass 换成 `immutables.Map`/`MappingProxyType` 并全量返修 reduce。
2. **seq 权威分配散落在 reduce 各处 → 反噬 P3**：终态唯一靠 `bus._closed`（传输层内存态），reduce 内 seq 手算 `run.seq+1(+i)`，两处口径不一致已致碰撞（#2）。P3 双游标（逻辑 seq + 物理 rowid，ADR-0011）叠加后，**半分配 seq 会与 `after_seq` 续传/exactly-once 记账冲突**。应把"本次 reduce 产生的事件按序取连续 seq、并推进 Run.seq 到最大事件 seq"做成单一函数。
3. **投影层是 identity → 反噬 P7/P9**：`project()` 无字段白名单/脱敏/raw-normalized 双轨。P7 Tauri / P9 OpenAI 兼容真接上时，**内部 `data` 结构会被 shell 直接依赖**；届时想"只增不改"已无隔离层可依（LiteLLM/供应商专有字段将渗进对外事件，换供应商即崩，违 02 §10）。
4. **死字段/未接接口是"假扩展位"**：`Budget` 四阈值、`SandboxPort`、`ToolRegistry`(ABC 无实现)、`LoopPolicy`、`PolicyPort.init/on_tool_result/dispose`、`WriteMemory`/`RequestCompactHint` Command —— 均**定义了却无消费者**。P2/P5 作者会**误信这些接缝已通**而在此之上叠逻辑（如以为"设了 `deadline_seconds` 就会超时"），反而掩盖真正要补的接线。至少应在代码里显式 `# NOT yet enforced until P#` 标注（部分已有 `# placeholder`，但 `Budget` 无）。
5. **长跑内存泄漏 → 反噬 P7**：`InProcessEventBus._subs`/`_closed` 按 run_id 只 append 不清（`events.py:63-64`），EventServer 常驻进程会**无界增长**；`cli.run_once` 每轮新建 `:memory:` store（`cli.py:87`），**跨进程根本不持久** → 与"持久化=断点续传"的 P3 叙事矛盾。
6. **NullSandbox/无 capability 路由的"安全假象" → 反噬 P2**：一旦 P2 引入 `write/bash`，当前 loop 会按"mutating→ask→批准即裸执行（无沙箱）"走，而 HARD-CONSTRAINTS T4/03 §10 要求"无后端→deny"。**把 deny-default 误实现成 ask-default** 是安全语义的实质倒退，且被 `read`-only 现状掩盖。
