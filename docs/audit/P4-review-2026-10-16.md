## 1. 一句话结论

**有条件 GO（CONDITIONAL GO）进入下一阶段**：P4 记忆子系统的**核心管道是真的**（写必经
`Command→reduce→kernel sink→MemoryStorePort`、混合检索/蒸馏/守卫/测试均有真实行为且实跑通过，
非薄桩、非 mock 冒充）；但存在 **2 项"文档宣称 ≠ 代码现实"**，按 AGENTS §5.5「Code merged, docs
stale = not done」在闭合前不得把 P4 当作**可运营的完整能力**：

- **写生产者未接线**：产品里记忆只能被读（`memory_search` 已注册），**没有任何出厂的写触发器**
  （无 `remember` 工具 / 无 surface 路由发 `WriteMemory`；`flush_run_to_daily` 有函数无调用者、
  run 完成边界不 flush），DoD「记住」仅由集成测试经真实 Command Inbox 手动提交证明；
- **CJK trigram 档位被谎报**：ADR-0026 / design-06 / plan 宣称三档（unicode61→**trigram-CJK**→LIKE），
  代码只有两档（unicode61→LIKE），且 `store_memory_sqlite.py:13` 过期注释、CHANGELOG「trigram
  真机 UNVERIFIED」把"未实现"包装成"已实现待验证"。

二者均非架构性 Blocker（管道正确、扩展无需破坏性改协议），但必须在把记忆交付为可用能力前修掉。

## 5. 扩展有害项（具体到哪个 Phase 反噬、怎么反噬）

1. **写生产者缺席 → P7（桌面）/ P8（多 agent）反噬**。现在 memory 只有读侧（`memory_search`）接进了
   surfaces，写侧全是"测试手搓 `WriteMemory` 塞 inbox"。P7 桌面要做"用户标记记住/编辑记忆"时，**没有
   一个 Command 生产者作为参照**，容易在 surfaces 里就地造第二写者（违 C16），或临时补一个绕过 inbox 的
   写路径。反噬形态：届时要在 surfaces↔kernel 之间补一条"记忆写"装配线，而 P4 声称的"run-完成 flush"
   从未接线，届时得先返工 flush 的触发点与失败语义（是否异步/有界重试，见 §6-3）。
2. **`PolicyView.memory` 无生产者 → P5/P8 策略消费反噬**。DoD④ 主证据靠 `MemoryStrategyConfig`+工具承载，
   `view.memory` 是空转接缝。P5（Skills/MCP）或 P8 若想真做"检索自动注入 prompt"，会发现填充逻辑无处附着
   （loop 故意不填、且不该填），只能在策略侧各自造检索调用 → 违反"换策略不动 loop"的原意，或反向逼 loop 加钩子。
3. **trigram 缺席 → P10 评测回归网反噬**。design/06 §6 已定 `CHUNKER_VERSION` 变更触发 `sync` 全量重建；
   若 P10 补 trigram FTS 表，属 schema 变更，`MEMORY_SCHEMA_VERSION` 需 bump，届时历史 `memory.db` 走
   fail-closed（`store:185-188`）→ 需要一次重建/迁移。现在把它当"已实现待验证"，会让 P10 低估这步成本。
   （好在真源是 md 文件、索引可 `sync` 重建，破坏半径有限——这是 §0"文件为真源"设计的正面收益。）
4. **压缩→L2' 桥只留接缝（正面，非有害）**：`disable_compaction=True`（`policy.py:88`）+ typed
   `MemoryWrite(kind=distill, covered_from/to/hash)`（`memory.py:128-156`）+ `RecoveryPointer` 快照 v3
   fail-closed（`snapshot.py:414-415`）——**该 draft 占位的接缝已标且已定型**，P10 接压缩生产者不需要破坏性
   改协议。此项属"扩展友好"，予以肯定，不算反噬。

## 6. 必须修清单（按修复顺序 + 每条附"能证伪它的测试应长什么样"）

1. **闭合写生产者（最高优先，A 类根因）**：二选一——(a) 在 run 完成边界**真接** `flush_run_to_daily`
   （`loop.py` 终态后、经注入 store），并定义失败/幂等/是否异步语义；或 (b) 提供一个发 `WriteMemory` 的
   出厂 affordance（如 `remember` 工具或 CLI/HTTP 写路由经 inbox）。同时把 ROADMAP §1.5 / CHANGELOG /
   design-06 §1 的"run-完成 flush 已交付"改成与实际一致。
   - *证伪测试*：一个集成测试跑真实 `DefaultTurnLoop` REPL 路径（非手动 `controller.submit`），让 agent
     经"某出厂入口"写一条唯一串 → 断言 `MEMORY_WRITTEN` 由该入口产生、落 md 真源、新 store 实例读回命中。
     当前**该测试写不出来**（无生产入口）——这正是能证伪"已交付写生产者"的判据。
2. **trigram 档位：实现或改口径（C/G/H 类）**：要么补 `chunks_fts_trigram` 三档降级（peer Cow
   `storage.py:452-463` 有现成范式），要么把 ADR-0026:7 / design-06:17 / plan §0:18 / CHANGELOG:66 全部改成
   "两档 unicode61→LIKE，CJK 靠 LIKE、trigram 显式后置 P10"，并删 `store_memory_sqlite.py:13` 过期注释、
   把 "UNVERIFIED" 改 "未实现/后置"。
   - *证伪测试*：对一段**连续中文无空格**语料（如 `"长期记忆系统偏好"`）写入后，用其中的**子串**查询
     `"记忆系统"`，断言命中。当前仅靠 LIKE 能过（子串匹配），但断言"经 trigram FTS 命中且 BM25 排序"会**判红**
     ——即无 `chunks_fts_trigram` 表就是没有该档，文档不得宣称。
3. **flush/蒸馏失败语义：补有界重试或改口径**：design-06 §1"异步后台、失败可重试"与 special check #3
   "transient 重试有界"。现状：flush 同步、无重试包装，仅靠 idempotency 保证"可安全重投"。要么加有界重试
   （N 次 + 释放回可重试），要么把"有界重试/异步后台"从宣称里去掉。
   - *证伪测试*：注入一个前 K 次抛 transient、第 K+1 次成功的 store，断 `deep_dream`/flush 在**有界次数内**
     最终成功且第 K+2 次为 no-op；当前无重试循环 → transient 一次即上抛，该测试判红。
4. **补 D③ 命名测试文件**（建议）：新增 `tests/integration/test_p4_memory_single_writer.py`，或在 plan §2
   D③ 更正为现有等价证据（AST self-test + `test_p4_memory_dod.py` + `test_reduce_memory.py`），消除"文件名对不上"。
5. **`view.memory` 填充方规划**（建议）：在 P5/P7 backlog 显式记一条"谁负责填 `PolicyView.memory`"，否则
   该接缝+`MemoryAwareReActPolicy` 会腐化成死演示。
6. **`memory_written` 事件 `source` 语义**（建议）：`reduce.py:226` 把 `source` 赋 `payload.kind.value`
   （kind 非 `MemorySource`），与白名单/投影语义混用；改为映射到真实 source 或删字段。
