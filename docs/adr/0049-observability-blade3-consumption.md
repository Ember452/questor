# ADR-0049: observability 刀 3 落地边界（`questor logs` 消费命令 + `--log-payload` preview 三闸 + usage 读侧聚合 + 投影 bus 级收口）

- 状态：✅（2026-10-19，P10 开工前置门；实现见 [`../plan/10-p10-hardening.md`](../plan/10-p10-hardening.md) Lane B，T0 先此 ADR）
- 背景：[`ADR-0027`](./0027-observability-logging-foundation.md) 落刀 1/刀 2（双通道 + `LogEntry` 中间表示 + 零原文 D4 + 按日切 D7 + 来源门 C20）；[`../docs/log/DESIGN.md`](../log/DESIGN.md) §14（消费面后置）、§12（`--log-payload` preview）、§18 刀 3 三件（消费命令 / OTel-metrics / preview 实装）。[`../docs/log/PLAN.md`](../log/PLAN.md) §7 偏差 #4：刀 2 把带外投影仍挂 `cli._stream` **逐消费者**、HTTP 侧未覆盖——[`../docs/pitfalls.md`](../pitfalls.md) #5 明令"收口只能 bus 级一处只读订阅"。[`ADR-0041`](./0041-fanout-budget-and-runaway-control.md):8 定"usage 归 per-run、聚合归 P10 观测面、基于全局 gseq watermark 不改内核不新增第二真相"。现场核：`surfaces/_assembly.py:43-51 reject_unimplemented_payload()` 对非 `off` 的 `QUESTOR_LOG_PAYLOAD` **拒绝启动**（preview 归本 ADR）；`observability/sink_file.py:111` `llm_file` 通道结构就位默认关；`usage_delta ∈ LIVE_ONLY`（kernel/events.py:31-33）**不入库且生产路径从不发射**、`run_completed.usage` 才是 durable（state/reduce.py:399）。
- 决策：
  1. **追踪/消费面全部基于 `event_log` 权威 + 旁路只读、零第二真相（C13/C20）**：新增 `python -m questor logs` 消费命令——主干查询走 `event_log`，按日 JSONL 作"账本外信息"旁路，二者按 `run_id+seq` 合并成时间线；`--timeline` 出 markdown+json 双份供贴 issue/交付报告；损坏行跳过并计 `malformed_lines`；**命令全程只读**（开 store 不取写锁、不触发 GC、不改状态；DESIGN §14）。GUI/Tauri 追踪面板 = 对同一事件协议的瘦客户端渲染（C14），本 ADR 只定**数据契约/命令**、真开窗口渲染标 UNVERIFIED。
  2. **带外投影收口为 bus 级一处只读订阅（pitfalls #5，消刀 2 偏差 #4）**：`log_envelope`/投影从各 surface 消费者上收到 `InProcessEventBus` 级**一条只读订阅**（`add_observer`），`emit` 对每条投影后 Envelope 恰触发一次、与订阅者数量无关。**覆盖面须含 CLI 直驱 + `http_sse` + OpenAI 兼容三生产者**（对抗评审 MAJ-9），否则收口后 CLI/兼容侧反丢投影。验收跑真文件 canary：开 2 并发 `/events` 订阅者跑同一 run，主干每 seq 恰一行。
  3. **`--log-payload`/`QUESTOR_LOG_PAYLOAD=truncate:N` preview 三闸（C20 不越界款：显式授权 + 独立通道 + 有界截断）**：preview **仅**写独立 `llm-<date>.jsonl`（开启即 `llm_file=True`）、必过 `redact.py` 脱敏、截断至 N；**主干 `questor-<date>.jsonl` 零原文不变（D4）**。允许进 preview 的键定死 = 仅 `arguments_preview`/`response_preview`（LLM 适配器作用域），**绝不进 `projection._DATA_KEYS`、绝不进主干**；非法值仍拒绝启动。`check_projection_whitelist.py --self-test` 须保持"加载荷键即红"。
  4. **usage per-run→session 聚合 = 读侧投影（ADR-0041/C13）**：`questor logs --totals` 跨 run 聚合**durable `run_completed.usage`**（经 `StorePort.replay_global`/`watermark` gseq 派生），**不依赖从不发射的 `usage_delta`（对抗评审 MAJ-4）**；**不改内核、不新增持久表、不落第二真相**（每次现算）。
  5. **OTel/metrics 移出本 Phase（对抗评审 MAJ-6，YAGNI + 守 D8）**：引第三方 OTel/metrics = 新依赖，与 [`ADR-0027`](./0027-observability-logging-foundation.md) D8「日志内核 stdlib-only、零新依赖」相左，且**不在 P10 DoD**（DoD 只需追踪面板基于事件流 + logs 命令 + preview）。真需求出现时由引入它的**那一个适配器**治理（pitfalls #4，内核九文件零依赖不破）、另立 ADR；本 Phase 仅保留"`trace_id` 作普通键进 `fields`"既有接缝（DESIGN §1 非目标）。
- 后果：正面——`event_log` 仍是唯一真相、观测面纯读旁路可丢弃；双投隐债（pitfalls #5）机制性收口；preview 在显式授权下可用而不破零原文默认。代价——投影收口触及 surfaces/kernel/events 接缝，须以三生产者覆盖测试兜；`questor logs` 作为新入口须自装配 console-only、绝不递归读自身产出。
- 备选（被否）：
  1. 投影继续逐消费者调用：多 surface 共享总线即翻倍、"任何新 surface 再踩一次"（pitfalls #5）→ 否。
  2. preview 默认写主干 / 进 `_DATA_KEYS`：D4 零原文当场旁路、日志比 DB 更易被顺手贴 issue → 否（C20）。
  3. usage 聚合走 `usage_delta` 或物化 session 总额表：前者无 durable 源（从不发射）、后者第二真相 → 否（MAJ-4/C13）。
  4. 本 Phase 就引 OTel/metrics：破 D8、非 DoD 必需、speculative infra → 否（MAJ-6，后置独立 ADR）。
