## 5. 扩展有害项与发布风险

1. **壳写死 `python` + `bundle.active:false`（专项5/6，节点 C）**：真实用户机上若无系统 Python 或版本不符，**桌面双击直接起不来**（连 dev 路径都要求 PATH 里有 `python`+装好 questor 依赖）。这是"能开窗口 demo"与"可发布产品"的分水岭——当前停在 demo 侧。**Phase：发布即暴雷。**
2. **无会话 token 的裸 loopback sidecar（安全）**：`http://127.0.0.1:<port>` 的 `/run`·`/events`·`/approvals/{id}/resolve` 无任何鉴权；本机任意进程可**驱动 agent 跑 run、伪造审批 allow、读全部事件**（审批弹窗是安全边界，被本地任意进程绕过 = HITL 形同虚设）。多用户/共享机/被入侵软件场景直接反噬。
3. **优雅关闭 no-op → 恒 35s 硬杀**：真实关窗体验=卡 35 秒再 Kill；SQLite 走 SIGTERM 落盘不确定，长 run 在途状态靠 reduce/append-only 兜，但**没有给 sidecar 一次体面 flush 的机会**。发布件不可接受。
4. **MCP 桌面路径没接线**：用户挂的 MCP server 在 GUI 里**永远不出现**（只在 CLI 生效），P5 卖点在桌面端缺失；且若后续图快把 discovery 塞 `start_run` 而不补 per-run teardown → MCP 子进程/stderr 句柄**泄漏**（run_registry 无对应清理）。
5. **字段级协议漂移无门（C15）**：`data` 字段名/schema 三处（contracts↔jsonschema↔TS）只在 type 粒度锁死；`generated/event.ts` 把 data 塌成 `{[k:string]:unknown}`，前端手写 cast——**新增/改名字段时 CI 全绿但前后端悄悄不一致**，多端（桌面/Web/移动/OpenAI）超大型项目里是长期最难查的一类 bug（正是 design/02 §6 line67 想防的）。
6. **无 CI 桌面 lane**：`cargo clippy/build/test`、`tsc`、`vitest`、`vite build`、`npm lint`（脚本根本不存在）**全部不在 CI**（只有 `ci-python.yml`；node 步仅跑 `check:protocol`）。桌面回归全靠本地手动，一次 Windows 上 clippy 判红就是证据——**发布里程碑不该没有桌面门。**
