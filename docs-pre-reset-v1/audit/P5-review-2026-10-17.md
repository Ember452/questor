## 4. 审计发现与"认/不认"判定（核心）
**我认并已修（本轮加固）：**
1. **[Blocker] 无发现上限** —— `McpManager.discover` 原样接收远程 server 全部工具，恶意/异常 server 可报海量工具撑爆 prompt/工具面。checklist §1"发现上限 256 超限拒接"直接命中。**修**：`manager._build_tools` 加 `MAX_DISCOVERED_TOOLS=256`，超限截断+出声。测试 `test_mcp_hardening.py::test_build_tools_caps_at_limit_and_warns`。
2. **[Blocker] 单个畸形远程 descriptor 可崩整个 run** —— 原 `for tool_def: tools.append(McpRemoteTool(...))` 在 `try`(list_tools) 之外；构造抛错会冒泡出 `discover`→ bootstrap → run_once，违 DoD③"绝不崩宿主"。**修**：`_build_tools` 逐工具 try/except，畸形只跳过该工具+出声。测试 `..._skips_malformed_descriptor_without_crashing`。
3. **[应修] `normalize_mcp_schema` 无递归深度上限** —— 病态深嵌套 schema → `RecursionError`（且落在 #2 的构造里）。**修**：`_MAX_SCHEMA_DEPTH=32`，超深截断返回浅拷贝。测试 `test_normalize_schema_survives_deep_nesting`（200 层不崩）。
4. **[应修] `${VAR}` 占位符未处理** —— checklist §1"占位符未识别即抛"。原实现把模板字面量直接递给子进程。**修**：`_build_entry` 检出未展开 `${...}` → fail-closed 跳过该 server+出声。测试 `test_unresolved_placeholder_server_is_skipped`。
5. **[应修/纵深] `McpServerConfig.env` 值可经 repr 泄出**（C17/C20）—— frozen dataclass 默认 repr 会打印 env 值。**修**：自定义 `__repr__` 只露键名。测试 `test_config_repr_hides_env_values`。

**我不认 / 判为 by-design / 已由 ADR 处置（不改，理由）：**
6. checklist §5"并行 gate 真实现" —— 经用户批准的 **ADR-0029 明确把 `parallel_safe`/`barrier` 移出 P5**；P5 执行严格串行，无任何派发路径读取这两个字段改变行为。这不是缺陷，是已落文档的范围决策（`contracts/tool.py` 注释、ROADMAP §1.5/§2.5 已同步）。
7. checklist §1"一 server 一专属 task 拥有 transport" —— 采用官方 SDK：每连接有自己的 anyio task group，`AsyncExitStack` 在 `run_once` 同一 task 进出（真子进程 roundtrip/断连测试绿，证明 transport 一致性与进程回收成立）。未照 DeepCode 自建 per-server 常驻 task 模型——是 ADR-0030 的取舍（复用 SDK 生命周期），非缺陷。
8. checklist §6"声明式条目 + commit-diff 增量应用（整表重建=反模式）" —— 该反模式针对**热插拔/常驻**能力面；P5 的 per-run 冻结快照重建 `RunToolSurface` 是其设计（run 内不变、C9/ADR-0009）。增量 diff 属 P9 插件宿主；记为**后续项**，非 P5 缺陷。
9. checklist §7"能力热变更发 `tools_changed` 投影事件" —— P5 无 run 内热变更路径；工具面在 `freeze_for_run` 冻结，符合"不改内核态"。无场景，不加。
10. MCP 子进程未走 `providers/process_runner`（与 ADR-0018 字面冲突）—— SDK 的 stdio_client 自带进程树终止 + env 白名单；`ProcessRunner.run()` 是 run-to-completion 模型，不适配长连双向 stdio。已在 plan/05 §8 偏差记录，并经 `check_layering_ast` 确认 `capabilities/mcp` 未 import `subprocess`/`process_runner`。
