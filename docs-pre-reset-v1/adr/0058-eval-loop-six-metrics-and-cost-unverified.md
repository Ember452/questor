# ADR-0058: G 评测环的六指标口径（任务集 + 判分器 + trace 形状；成本只到 token）

- 状态：✅（2026-10-21，B12/c1–c3）
- 背景：v3 把"个人 agent 能不能变强"从感觉改成六个数（§10）。难点不是算，而是**口径一旦选错，
  指标就会自证其美**：把"搜索命中"当"被消费"，写入噪声率永远 0；把"系统自己得到的命中集"当分母，
  召回命中率永远 100%；把没有价目表的 token 换算成美元，就是给一个凭空的汇率盖章。同时 questor
  此前的"评测"只有两个文件（P10 三条 + P4 一条），没有任务集，任何改动都说不清"变好还是变坏"。
- 决策：
  1. **任务集 = 输入 + 允许工具集 + provider 脚本 + 判分器 + trace 形状**五件（`tests/evals/tasks.py`，
     10 个任务）。形状参照 wuu `evalharness/trace.go`，但判据只读 **durable 事实**（事件流 /
     `Domain_State` / 记忆库正文），绝不读模型口气。
  2. **trace 判据是子序列，不是金标快照**：顺序必须对，中间允许出现新事件。否则任何 additive
     事件都会把评测打红，评测就会反过来阻止协议演进（本项目协议只增不改，这条尤其重要）。
  3. **判分器一次报全部失败项**（不是第一个）：红任务必须说清是哪条判据红。
  4. **六指标的分母定义**（`tests/evals/metrics.py`，全纯函数、零 IO）：
     | 指标 | 分子 / 分母 | 为什么只能是它 |
     |---|---|---|
     | 召回命中率 | 人工标注"应被引用"条目中被引用的 / 应被引用总数 | 用命中集当分母=被测系统自己出题 |
     | 遗忘率 | 人工标注应记事实中未出现在记忆正文的 / 应记总数 | 启发式猜"该记什么"会把指标变成自证 |
     | 写入噪声率 | 满 30d 且**条目级**从未被消费的 / 满 30d 的写入条数 | kind 级算不出；未到期条目**两头都不进**，否则新写入稀释分母、永不红 |
     | 重复提醒率 | `attempts ≥ 2` 的义务 / 义务数 | `recovered` 只进 note：崩溃重投≠静默重投 |
     | 撤回率 | durable `memory_deleted` / `memory_written` | 与撤回史同一出处（§20 C-7 无历史表），两处数会得两个答案 |
     | 每成功任务成本 | token 总数 / 成功任务数 | **`run_completed.usage` 里没有钱** |
  5. **成本标 UNVERIFIED，不是免责声明而是判据**：没有价目表时 `verified=False` 且 note 写明需价目表；
     传了表（`{"input": .., "output": ..}` 每百万 token）才算出 `cost_usd` 并转 `verified=True`。
     本仓刻意不内置任何汇率（§17-9）。
  6. **分母为 0 → `value=None`，绝不返回 0.0**："没有样本"与"样本全过"是两件事，看板的 0 会把二者
     合并成同一个假象。`test_metrics_refuse_to_invent_zeroes` 把六条都钉住。
  7. **三条防自证任务进任务集**：撤回（`memory_deleted` 真发）、幂等重写（同 `idempotency_key`
     返回原 receipt、不重复 append）、大输出归档（C-1 端到端，prompt 只该留有界 preview）。
     前两条正是噪声率与撤回率的口径入口；不测它们，两个指标就是空中楼阁。
  8. **命令类场景走同一咽喉**：harness 的写/撤回/重写步骤都在一个未终态伴跑 run 上经
     `loop._transition` + emit 完成——终态 run 拒收后续命令是正确行为，不能用它来"造场景"。
  9. **F 自进化环仍不在本刀**：§13 明写 F 环仅在 B12 之后立项；本 ADR 只交付"能出数的六指标"，
     不实现影子评测/自动改策略（那需要 B12 的看板先成立）。
- 后果：
  - 正面：任何记忆/召回/调度/压缩改动从此有 10 个可复现任务与 6 个口径明确的数；
    确定性判据（两次跑同事件序列）挡住"时序漂移冒充通过"。
  - 代价：任务集与判分器本身也是被测物——加任务要同时加判据并保持 id 唯一
    （`test_task_set_is_ten_and_all_ids_unique` 钉住数量）；人工标注（应记事实、应引用条目）
    是**必须由人维护**的资产，标注偷懒=指标失真；`chars/4` 的 token 折算只是估算（评测里不做阈值
    决策，只用于讲给 §7.1 的 token 口径听）。
  - 需持续守：不得把 `memory_search` 命中算进消费（§6.3 硬规定）；不得给成本指标内置汇率；
    不得把 trace 判据改成全等快照。
- 备选（被否）：
  1. **用命中集当召回分母**：否——永远 100%，且掩盖"该召回的没召回"。
  2. **kind 级消费打点算噪声率**：否——§10 明写 kind 级算不出此指标。
  3. **分母 0 时返回 0.0**：否——看板无法区分"无数据"与"全通过"。
  4. **内置一张模型价目表**：否——本仓没有任何汇率实测依据（§17-9），编一张就是把假设写成结论。
  5. **真实 LLM 跑评测**：否——引入网络与不确定性，判据就无法复现；真摘要质量仍标 UNVERIFIED。

  `ADR-0056`（`memory_deleted` 与不建历史表）、`ADR-0057`（窗口/成本口径依赖的 usage 信号源）。
