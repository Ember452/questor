# Questor 项目宪章（我们要做什么）

> 这是 Questor 项目的顶层定位与蓝图，后续所有设计 / spec / 计划的母文档。

---

## 1. 一句话定位

**从零自研一个"超级智能体"的运行时底座（Agent Harness）+ 其上可插拔的 Agent 策略层，做成一个长期的、可超大规模扩展的桌面通用个人 Agent。**

不从任何现成项目复制——**所有设计与代码均自研、定于本仓 `docs/`**。

## 2. 已定的关键决策

| 维度 | 决定 |
|---|---|
| 代码来源 | **从零自研** |
| 语言/运行时 | **Python**（LiteLLM / MCP 原生生态最肥、单人长期维护快）；Go 仅备选 |
| 桌面壳 | **已定：Tauri v2 + Web 前端（React/Svelte + TS）+ Python sidecar**；UI 只当瘦客户端经事件协议连后端，一份 UI 复用到 桌面/网页/移动 |
| 模型接入 | **LiteLLM（SDK/网关）**做多供应商路由 + 熔断/fallback/成本；预留 BYOM（把别的 Agent 当引擎）的口子 |
| 提交口径 | commit 用**开发口吻描述真实工程动作**；**不伪造时间戳/作者**（真实增量开发本身就是可信历史） |

## 3. 架构分层（第一步定死的边界）

```
③ Agent 层  = 可插拔"策略"：规划/ReAct、反思、记忆策略、提示词
                —— 只读状态快照、返回决策(调哪个工具/直接答/是否写记忆)
                   绝不自己碰沙箱 / 持久化
② Harness    = 运行时底座(引擎)：turn 循环驱动、核心状态模型、工具路由、
                沙箱/权限、持久化/断点、事件广播
① 底座        = Provider: LiteLLM 多模型  |  Store: SQLite / 向量库
④ Shell        = Tauri 桌面 / Web / CLI / (IM) / OpenAI 兼容API（都经事件协议消费）
```

三条精度补丁（防边界走偏）：
- **A 谁调谁**：Harness 驱动循环、把状态交给 Agent 策略、拿回决策去执行；换模型/换算法只动策略层，不动 Harness。
- **B 两类通道**：`State`（权威·可序列化·可回放）与 `Runtime 瞬态`（取消/超时/进度/在途 delta，**不落状态**）分开；策略拿的是**按字段暴露的只读视图**（COW/结构共享，不每轮全量深拷）。
- **C 事件 = 投影**：事件协议是"状态转移 + 流式/瞬态信号"的广播，不是把状态整块序列化。状态类事件对齐断点粒度（可回放），流式类只做实时显示。

## 4. 设计次序（先地基后装饰）

```
1 定分层边界(Agent↔Harness↔Provider/Shell)          ✅
2 定【核心状态模型】schema  = Harness 唯一可信状态    ◀ 当前
3 定事件协议（状态转移 + 流式的投影）
4 定工具接口 + 沙箱/权限
5 定 turn 循环骨架（阶段机）
   → 汇总成 design spec → 审 → 出实现计划
```

**核心状态模型**是基石，含 6 块：会话上下文 / 任务树 / 工具调用记录 / 断点标记 / 权限上下文 / 错误栈。事件协议是它的投影，故**先定状态、再定事件**。

### 事件协议 v0 要点（草案，第 3 步细化）
- **单一 canonical 模型 + 薄适配器**（桌面/Web、IM 卡片、OpenAI 兼容各一份投影）。
- **信封**：`{ v, seq, run_id, turn?, type, ts, data }`；`seq` 单调可续传；关联键 `run_id/turn/tool_call_id/item_id` 定了不改。
- **演进铁律**：未知 `type` 静默忽略；`data` 只增不改不删；破坏性变更才 bump `v`。→ 保证"以后随便加、不用协调"。
- **可扩展验收**：语音/子agent/产物/HITL审批/MCP热增/成本/心跳 等未来扩展都应**只加事件、不改信封**；做不到即协议设计错。

## 6. 建造顺序（纵切优先，每块跑通再加）

```
心脏① 最小可跑循环(单模型 + 1工具 + 流式 + 取消)
 → 记忆(短期 → 三层+蒸馏) → 能力(工具/skills/MCP/沙箱) → 上下文压缩
 → 多agent/子agent → 桌面壳(Tauri) → BYOM/外挂引擎 → 插件宿主(注册+生命周期)
```
每个纵切固定四步：**设计 → 定“失败模式清单”再自研 → 分层验证(单元 + 能力对照 + 任务级回归) → commit**。

## 7. 长期护栏

- 分层验证（每纵切当场验，别攒到最后）；任务级回归网（改循环/压缩前必备）。
- 协议演进铁律（只增不改 / 未知即忽略）+ CI：冷导入、回归测试。
- 提交历史 = 真实增量开发的自然产物。
